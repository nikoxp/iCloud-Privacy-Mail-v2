# v2 缺口审计

> 历史文档：本页记录早期迁移对照。最新功能、质量与安全结论以 [`07-代码与安全审计.md`](07-代码与安全审计.md) 为准。

审计对象：旧项目 `iCloud-Privacy-Mail` 与新项目 `iCloud-Privacy-Mail-v2`。本次只读检查旧项目路由、协议客户端、状态模型、迁移工具和 Vue 页面；原项目没有被本轮修改。

## 当前结论

P0、P1、P2 的核心个人使用闭环已经迁移。v2 继续保持单管理员、本地 JSON、无多用户注册和无 `/manage`。剩余项目主要是公网加固和可选更新功能，不影响本地运行。

## 数据基座

- `domain.SchemaVersion` 为 3。
- `create_settings`、owner 字段、`last_sync_uid`、`last_code_message_id`、`last_code_at` 已保存。
- 旧 `icloud_session` / `icloud_sessions` 会自动适配为 typed `ICloudSession`，登录态按账号合并。
- 迁移报告包含旧用户、登录态、创建设置、孤立邮箱数量；旧控制台 Web 会话不迁移。
- 状态文件仍包含 Apple Cookie、scnt、API key 和 IMAP App 专用密码；公网部署前应增加加密存储或系统密钥环。

## 仍需后置的事项

1. 公网部署：Secure Cookie、CSRF、登录失败限制、反向代理和审计 IP。
2. 敏感字段加密：状态文件密钥管理和导出文件二次保护。
3. 自动更新：仅在确认部署方式、产物签名和回滚策略后再实现程序替换。
4. 高并发场景：当前同一账号的并发同步会合并；公网大并发时再评估跨进程任务队列和集中式状态存储。

## 明确移除的内容

多用户注册、用户管理页、管理员数据页和 `/manage` 不属于 v2 目标，不应重新加入路由、导航或迁移逻辑。

旧版手动插入邮件接口属于调试数据能力，本项目按“不新增测试代码”的要求移除。新版只迁移安全的更新检查和公告展示，不迁移旧版直接替换程序的行为。
