## 1. 审计结论

当前代码已经覆盖个人本地使用的主要闭环：管理员登录、Apple Account/iCloud Web 登录与 2FA、IMAP、隐私邮箱创建/同步/删除、邮件与验证码、自动创建、公共接口和数据导出。`/manage` 与多用户体系按项目目标移除，不属于遗漏。

本地默认绑定 `127.0.0.1` 时可以继续个人使用；公网发布前仍有 4 组 P0 加固事项：Host/DNS rebinding 防护、登录与公共接口限流、管理写接口 Origin/CSRF 校验、公共验证码访问控制。状态文件中的 Apple/IMAP 敏感信息也需要加密或系统密钥环保护。

本次没有发现 SQL 注入、命令注入、模板注入、前端 `v-html`/`eval`、开放 CORS、目录遍历式下载或已知依赖漏洞。项目没有 SQL 数据库，Go 模块只使用标准库。

## 4. 功能与质量缺口

### P0：建议优先处理

#### F-01 调度器快速停止后重启存在跨任务竞争

证据：[`internal/scheduler/service.go`](../internal/scheduler/service.go#L72) 的 `Start` 会替换共享 `state` 和 `cancel`；旧 goroutine 收到取消后调用同一个 [`finish`](../internal/scheduler/service.go#L231)。如果用户快速执行“停止 → 重新启动”，旧 goroutine 可能在新任务开始后把新任务标为 `stopped`，并清空新任务的 `cancel`。

影响：页面显示任务已停止，实际新 goroutine状态与控制台不一致；后续停止操作也可能失效。

建议：给每次启动生成 `runID`，`run`、`runRound`、`finish` 更新状态前校验当前 `runID`；`finish` 只清理属于自己的 cancel。

### P1：影响使用完整性

#### F-02 已有备注清空操作未生效

证据：[`internal/store/mailbox.go`](../internal/store/mailbox.go#L113) 的 `SetMailboxStatus` 只在 `strings.TrimSpace(note) != ""` 时更新备注。

影响：详情页把备注删空并保存后，旧备注仍在。

建议：用 `*string` 区分“字段未提交”和“明确提交空字符串”，或让状态接口始终覆盖备注。

#### F-03 远端同步只新增/更新，不对账远端已消失邮箱

证据：[`internal/mailbox/service.go`](../internal/mailbox/service.go#L138) 的 `SyncRemote` 只遍历 Apple 返回的远端邮箱并执行 upsert。

影响：邮箱在 Apple 其他客户端被删除后，本地记录仍可能显示 `icloud_active=true`，直到用户手动处理。

建议：同步前建立本地账号邮箱集合；远端列表完成后，把未匹配记录标记为 iCloud 停用，并让用户选择保留本地或清理。

#### F-04 自动创建运行状态和日志只在内存

证据：[`internal/scheduler/service.go`](../internal/scheduler/service.go#L59) 的 `State` 保存在 `Service` 内存中。

影响：服务重启后运行状态、成功/失败计数和最多 200 条调度日志全部重置；已启动任务不会恢复。

建议：把调度配置、最近状态和日志摘要写入 store；重启时明确恢复任务或显示“上次异常中断”。

#### F-05 后端缺少业务字段最大值校验

证据：[`internal/scheduler/service.go`](../internal/scheduler/service.go#L244) 只处理空值和最小值；公共 claim 的 `project`/`purpose` 主要依赖 1 MiB 总请求体限制。

影响：绕过前端可提交很大的标签、备注和极大调度间隔，增加状态文件体积并产生异常时间计算。

建议：在服务层统一限制标签、备注、关键词、项目名和时间间隔；返回稳定的字段错误码。

### P2：性能、维护和体验

#### F-06 本地邮件没有保留策略

`Events` 最多保留 500 条，调度日志最多 200 条，但 `State.Messages` 没有数量或时间限制。长期监听会让 `state.json` 持续增大。

建议：按邮箱设置最大邮件数或保留天数；清理时同步重算 `receive_count` 和最近验证码游标。

#### F-07 批量 IMAP 同步写盘次数偏多

[`Store.UpsertMessage`](../internal/store/mailbox.go#L164) 每新增一封邮件都会序列化并保存完整状态，随后每个邮箱还会保存同步游标。

影响：邮箱和邮件较多时磁盘写入放大，接口响应变慢。

建议：增加 store 批量事务方法，在一次锁和一次原子保存中写入同账号的消息与游标。

#### F-08 Staticcheck 清理项

Staticcheck 共报告 25 项：

- 14 个中文错误文本首字符大写的风格提示 `ST1005`。
- 8 个未使用声明 `U1000`。
- 2 个结构体可直接转换提示 `S1016`。
- 1 个初始化后总被覆盖的 `messagesByMailbox` 值 `SA4006`。

其中 `SA4006` 与未使用声明适合优先清理；其余不影响运行结果。

#### F-09 通用弹窗缺少完整焦点循环

确认弹窗有初始焦点、Escape 关闭和 `aria-modal`，但 Tab 仍可能离开弹窗。建议为确认弹窗和业务详情弹窗实现 focus trap，并在关闭后恢复触发按钮焦点。

#### F-10 自动替换程序仍未实现

`update_enabled`、`update_repository` 已连接受登录保护的更新检查接口、系统设置版本卡片、侧栏版本信息和公告中心。检查范围包括 GitHub Release、默认分支最新提交与仓库公告文件，并限制为固定 GitHub API 地址。当前不会下载或替换程序，因此数字签名、优雅停机、守护进程重启和失败回滚仍属于以后实现自动更新时的必要条件。

## 5. 安全问题

风险级别按“公网部署且攻击者可访问服务”评估。本地仅绑定 `127.0.0.1` 时，多数风险的暴露面明显下降。

### 高风险

#### S-01 未校验 Host，存在本地服务 DNS rebinding 风险

证据：[`Server.ServeHTTP`](../internal/httpapi/server.go#L189) 直接把请求交给路由；首次初始化接口 [`POST /api/auth/setup`](../internal/httpapi/server.go#L77) 在管理员尚未创建时无需认证。隔离验证中，带任意 `Host: attacker.example` 的请求仍返回 HTTP 200。

影响：恶意网页在浏览器 DNS 重绑定条件下可能访问本机服务；首次运行窗口尤其敏感。Host 还参与生成邮箱 API 链接。

建议：

- 本地模式只接受 `localhost`、`127.0.0.1[:port]` 和明确配置的 Host。
- 公网模式显式配置 `allowed_hosts` 与 `public_base_url`。
- 拒绝不可信 `X-Forwarded-Proto`，只在可信反向代理来源下读取转发头。
- 首次设置可增加一次性启动 Token，显示在本机终端。

#### S-02 登录和公共接口没有速率限制

涉及接口：管理员登录、首次设置、公共 claim/lookup、邮箱取码、公共验证码查询。

影响：公网下会暴露密码猜测、邮箱枚举和 IMAP/Apple 请求资源消耗。公共取码虽然会合并同一账号的同步，但跨邮箱、跨账号请求仍可并发触发外部调用。

建议：按 IP、账号、邮箱和全局并发分别限流；登录失败使用指数退避；同步请求设置队列、每账号并发 1 和全局上限。

#### S-03 公共验证码页面按邮箱地址直接返回验证码

证据：[`handlePublicMailboxCode`](../internal/httpapi/p2.go#L115) 在公共页面上下文中只检查开关，不校验 API Key；邮箱不存在、API 停用和 iCloud 停用返回不同错误。

影响：知道或猜到完整邮箱的人可以读取验证码，不同响应还会帮助判断邮箱是否存在和处于何种状态。

建议：增加页面访问 Key、一次性领取凭证或短期签名链接；所有失败统一响应；限制查询次数并记录安全事件。

### 中风险

#### S-04 管理写接口没有 Origin/CSRF 校验

证据：认证只检查 Cookie，[`protected`](../internal/httpapi/server.go#L196) 没有 Origin/Referer 或 CSRF Token 校验。隔离验证中，携带有效 Cookie 且设置跨站 Origin 的写请求仍返回 HTTP 200。

现有缓解：Cookie 使用 SameSite Strict，普通跨站表单通常不会携带该 Cookie。

剩余风险：DNS rebinding、错误配置的代理和未来调整 SameSite 后会放大影响。

建议：对 POST/PUT/DELETE 校验允许的 Origin，并加入双提交或会话绑定的 CSRF Token。

#### S-05 Apple、IMAP 和 API 密钥明文保存在 JSON

敏感字段包括 Apple Cookie、`scnt`、`data_access_token`、IMAP App 专用密码、邮箱 API Token 和公共 API Key。

现有保护：`data/state.json` 写入权限为 `0600`，目录为 `0700`。

问题：当前工作区 `config.json` 权限是 `0644`；如果写入备用 API Key 或 Apple Account API Key，同一台机器上的其他本地用户可能读取。

建议：启动时检查并修正配置权限；优先使用 macOS Keychain、系统密钥环或由环境变量提供的主密钥加密敏感字段。

#### S-06 敏感导出响应缺少禁止缓存头

证据：[`writeDownload`](../internal/httpapi/p2.go#L441) 只设置 `Content-Type` 和 `Content-Disposition`。

影响：完整导出包含 Apple 登录态和 App 专用密码，浏览器、代理或网关可能缓存响应。

建议：增加 `Cache-Control: no-store, private`、`Pragma: no-cache`、`X-Content-Type-Options: nosniff`，公网部署时限制反向代理缓存。

#### S-07 API Token 支持放在 URL 查询参数

证据：[`mailboxAPIURL`](../internal/httpapi/p2.go#L461) 生成 `?key=...` 链接，授权函数也接受查询参数。

影响：Token 可能进入浏览器历史、访问日志、代理日志和截图。

现有缓解：服务设置 `Referrer-Policy: same-origin`。

建议：文档和 SDK 默认使用 `X-API-Key` 或 Bearer Header；页面只在用户显式选择时生成带 Key URL；提供 Token 轮换接口。

#### S-08 对外 API URL 信任请求 Host 和转发协议

没有配置 `public_base_url` 时，服务使用 `r.Host` 和 `X-Forwarded-Proto` 生成导出链接。攻击者可污染导出内容中的主机名或协议。

建议：公网部署强制配置 `public_base_url`；转发头只信任明确的反向代理；与 S-01 共用 Host allowlist。

#### S-09 Apple 返回的服务 URL缺少显式 allowlist

证据：iCloud validate 会保存 `premiummailsettings`、`mccgateway` 和 `mail` URL；[`endpointWithBase`](../internal/protocol/icloud_client.go#L2169) 解析后直接请求。

攻击路径要求 Apple 响应、迁移文件或本地状态被篡改，因此优先级低于公开接口问题。

建议：只允许 HTTPS，并校验主机属于 Apple/iCloud 预期域名集合；拒绝 loopback、私网和非标准端口。

### 低风险与加固项

#### S-10 安全响应头不完整

已有 `X-Content-Type-Options`、`X-Frame-Options: DENY`、`Referrer-Policy`；缺少 Content-Security-Policy 和 Permissions-Policy。

建议先以 Report-Only 验证 CSP，再固定 `default-src 'self'`、脚本、样式、连接和图片来源。

#### S-11 密码摘要成本偏低于较新的推荐值

管理员密码使用随机盐 PBKDF2-SHA256，迭代 120000 次，比较使用常量时间。算法和实现方向正确，但公网服务可提高迭代次数，并在登录时自动升级旧摘要。

#### S-12 会话过期记录只在新登录时持久化清理

认证会跳过过期会话，但不会在每次校验时从状态文件删除；过期项主要在新登录时清理。建议周期清理或在保存其他状态时清理。

#### S-13 Apple 调试日志可能包含敏感响应

开启 `IPM_DEBUG_APPLE_AUTH=1` 后会输出 Apple 协议调试内容。生产环境应保持关闭，调试输出应只保留指纹和状态码。

#### S-14 状态文件原子重命名后未同步目录

文件本身已经 `Sync`，但重命名后没有对父目录执行 `fsync`。普通退出和崩溃场景通常正常；严格掉电一致性可补充目录同步。

## 6. 已确认的安全实践

- 管理员密码使用 PBKDF2-SHA256、随机盐和常量时间比较。
- 控制台会话 Token 使用加密随机数，状态文件只保存 SHA-256 摘要。
- Cookie 为 HttpOnly、SameSite Strict，Secure 可配置。
- API Key 和邮箱 Token 使用常量时间比较。
- JSON 请求体限制约 1 MiB，并拒绝尾随第二个 JSON 对象。
- Apple/iCloud HTTP 客户端设置超时，使用系统 TLS 验证。
- IMAP 使用 TLS 1.2 或更高并校验 `imap.mail.me.com` 证书名。
- 没有开放 CORS。
- Vue 页面没有 `v-html`、`innerHTML`、`eval` 或动态脚本注入。
- Vue 插值默认 HTML 转义，邮件正文以文本形式显示。
- 状态文件采用临时文件、文件同步、原子替换和 `0600` 权限。
- 邮箱列表主动移除 API Token；只有登录后的详情和导出按需读取。
- 弹窗使用 Teleport、遮罩、Escape 和 `aria-modal`，背景点击不会穿透。

| --- | --- |

## 8. 修复顺序

### P0：公网前完成

1. Host allowlist、固定 `public_base_url`、可信代理配置。
2. 登录、公共验证码、公共取号和同步请求限流。
3. 管理写接口 Origin/CSRF 防护。
4. 公共验证码页面访问凭证、统一错误和审计记录。
5. HTTPS、`secure_cookie=true`、敏感状态加密、配置权限 `0600`。

### P1：下一轮功能修复

1. 调度器引入 `runID`，修复停止后快速重启竞争。
2. 支持清空邮箱备注。

## 9. 最终判断

当前版本适合“单用户、本机运行、仅自己使用”的目标，核心业务已从参考项目迁移并形成清晰页面。它还不是直接暴露到公网的安全成品：公共验证码、Host、限流、CSRF 和敏感数据保护应视为公网发布门槛。

本报告是当前代码快照的审计结果。后续修复 P0/P1 后，应重新执行同一组静态扫描、接口验证和页面巡检，并更新本文档日期与结论。
