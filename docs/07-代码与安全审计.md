> 审计日期：2026-08-15

## 1. 结论摘要

项目已形成完整的单管理员、本地使用闭环：Apple Account/iCloud Web 登录与 2FA、IMAP、隐私邮箱、邮件与验证码、自动创建、公共租约、SQLite、SSE、导出、后台清理和新版 UI 均有实际实现与测试覆盖。

本地默认绑定 `127.0.0.1` 的使用方式风险相对可控。直接部署到公网前，优先处理以下问题：

1. Apple 远端邮件删除使用邮箱地址子串匹配，相似地址可能误匹配并删除其他邮箱邮件。
2. Go 1.26.5 标准库存在 5 条代码可达漏洞，扫描结果标记在 Go 1.26.6 修复。
3. Host 未做 allowlist，登录、首次设置和公共接口缺少限流。
4. 公共验证码只凭邮箱地址即可查询，并通过差异错误暴露邮箱状态。
5. 管理写接口缺少 Origin/CSRF 校验。
6. Apple 返回并持久化的服务 URL 缺少 Apple/iCloud 域名 allowlist。

本轮没有发现开放 CORS、前端 `v-html`/`innerHTML`/`eval`、命令注入入口或远程用户可控的通用 SQL 表名。`npm audit` 未发现前端依赖漏洞。SQLite 敏感字段加密、API 全局 `no-store`、数据库文件权限和 SSE 断线回放均已实现。

## 4. 高优先级问题

### H-01 远端邮件删除使用邮箱子串匹配

证据：[`internal/protocol/icloud_client.go`](../internal/protocol/icloud_client.go#L2071) 在清理目标邮箱邮件时调用 `containsFold(recipients, email)`；[`containsFold`](../internal/protocol/icloud_client.go#L2701) 实际为大小写不敏感的 `strings.Contains`。

示例：目标邮箱为 `abc@icloud.com`，收件人文本中若包含更长的相似地址，子串匹配可能把该邮件识别为目标邮箱邮件。

影响：按邮箱清理和邮箱删除前清理可能选中其他隐私邮箱的邮件，属于远端破坏性操作的边界错误。

修复建议：

1. 解析 To/Cc/Bcc/Delivered-To 等收件字段为规范邮箱地址集合。
2. 统一去除展示名和尖括号，对域名与本地部分按协议要求规范化。
3. 使用完整邮箱地址等值比较，不使用任意正文或序列化字符串的子串匹配。
4. 删除前记录匹配来源、目标邮箱和远端 message ID，并为相似邮箱增加回归测试。

### H-03 Host 与外部 URL 生成缺少可信边界

证据：[`Server.ServeHTTP`](../internal/httpapi/server.go#L400) 未校验 `r.Host`。未配置 `public_base_url` 时，[`publicBaseURL`](../internal/httpapi/p2.go#L483) 使用请求 Host，并直接参考 `X-Forwarded-Proto`。

影响：本地服务存在 DNS rebinding 暴露面；公网导出的取码 URL 也可能被 Host 或转发协议污染。

修复建议：

- 新增 `allowed_hosts`，本地默认只允许 `localhost`、`127.0.0.1` 和 `[::1]`。
- 公网模式强制设置 `public_base_url`。
- 只有来自明确代理 IP 的请求才读取 `Forwarded`/`X-Forwarded-*`。
- 首次设置接口增加一次性终端 Token 或本机来源限制。

### H-04 登录与公共接口缺少限流

涉及管理员登录、首次设置、公共 claim/lookup、邮箱取码和公共验证码查询。

影响：公网下可能出现密码猜测、邮箱状态枚举、大量租约请求以及 Apple/IMAP 外部请求放大。

修复建议：按 IP、管理员名、project、邮箱、Apple 账号和全局并发分别限制；登录失败使用退避；Apple/IMAP 同账号外部调用保持并发 1 并设置全局队列上限。

### H-05 公共验证码访问控制不足

公共验证码页面开启后，只知道完整邮箱地址即可查询验证码。不存在、API 关闭、iCloud 停用和未收到验证码会返回不同结果，可用于枚举邮箱状态。

修复建议：使用租约凭证、短期签名链接或独立访问 Key；统一失败状态与耗时；限制查询频率；记录 project、邮箱摘要、来源和结果，不记录验证码原文。

## 5. 中优先级问题

### M-01 管理写接口缺少 Origin/CSRF 校验

[`Server.protected`](../internal/httpapi/server.go#L410) 只验证管理员会话。SameSite Strict Cookie 对常规跨站请求有缓解作用，但 Host/DNS rebinding、代理错误配置和未来 Cookie 策略变化仍会扩大风险。

建议对 POST/PUT/DELETE 校验允许的 Origin，并使用会话绑定 CSRF Token。

### M-02 Apple 服务 URL 缺少域名 allowlist

iCloud 登录响应中的 `premiummailsettings`、`mccgateway` 和 `mail` URL 会持久化，后续 [`endpointWithBase`](../internal/protocol/icloud_client.go#L2561) 解析后发起请求。当前缺少 HTTPS、预期 Apple/iCloud 域名、端口和私网地址校验。

建议仅允许 HTTPS、标准端口与明确 Apple/iCloud 后缀，拒绝 loopback、链路本地、私网 IP 和重定向到非 Apple 域名。

### M-03 API Key 支持 URL 查询参数

[`globalAPIKeyMatches`](../internal/httpapi/p2.go#L499) 和邮箱 Token 校验同时接受 `?key=`、`X-API-Key` 与 Bearer Token；导出取码地址也会生成带查询 Key 的 URL。

影响：Key 可能进入浏览器历史、代理日志、访问日志和截图。

建议文档和 SDK 默认只使用 Header；页面显式提示带 Key URL 的泄漏风险；增加 Token 轮换和失效接口。

### M-04 业务字段缺少统一最大值

标签、备注、project、purpose、关键词和调度随机范围主要依赖请求体总大小与前端限制。绕过前端可写入很长内容或异常大的时间范围。

建议在服务层定义统一常量，返回字段级中文错误，并对随机范围的最小值、最大值和跨度设置上限。

### M-05 远端邮箱同步不对账删除记录

[`SyncRemote`](../internal/mailbox/service.go#L206) 遍历 Apple 返回结果并 upsert，没有把本地存在但远端已消失的邮箱标记为停用。

影响：用户从其他 Apple 客户端删除邮箱后，本地可能继续显示 `icloud_active=true`。

建议同步完成后对账号邮箱做集合差异，把缺失记录标记为远端停用，并让管理员选择保留或清除本地数据。

### M-06 完整运行数据导出包含敏感信息

管理员主动导出的完整运行数据包含 Cookie、登录态、API Key 和 IMAP App 专用密码。所有 `/api/` 响应已由 [`ServeHTTP`](../internal/httpapi/server.go#L400) 设置 `Cache-Control: no-store`，旧报告中“导出缺少 no-store”的结论已经过时。

后续建议增加导出二次确认、操作审计、可选字段排除和密码保护压缩包。

### M-07 管理员密码摘要成本可升级

管理员密码使用随机盐 PBKDF2-SHA256 120000 次，并使用常量时间比较。公网部署可提高成本，摘要中保留版本和迭代次数，并在登录成功时自动升级旧摘要。

## 6. 低优先级与维护项

### L-01 安全响应头

已有 `X-Content-Type-Options`、`X-Frame-Options: DENY`、`Referrer-Policy` 和 API `Cache-Control: no-store`。尚缺 CSP 与 Permissions-Policy。

建议先部署 CSP Report-Only，再收敛到 `default-src 'self'`，并明确 SSE `connect-src`。

### L-02 弹窗焦点循环

通用确认弹窗已有遮罩、Escape、`aria-modal` 和初始焦点，仍需完整 focus trap 与关闭后焦点恢复。

### L-03 Apple 调试日志

`IPM_DEBUG_APPLE_AUTH=1` 会输出 Apple 响应正文。该变量只应在临时排查时开启，并继续避免把 Cookie、验证码或 Token 写入长期日志。

### L-04 Staticcheck 清理

共 29 项：

- 17 个 `ST1005`：中文错误文本首字符风格。
- 9 个 `U1000`：未使用声明。
- 2 个 `S1016`：结构体可直接转换。
- 1 个 `SA4006`：[`internal/mailbox/service.go`](../internal/mailbox/service.go#L805) 的 `messagesByMailbox` 初值未使用。

`SA4006` 和 `U1000` 适合优先清理，其余主要影响维护质量。

## 7. 已确认的安全与数据实践

- SQLite 使用 WAL、单连接写事务、逐版本迁移和关系保护。
- Apple Cookie、登录态、IMAP 密码、邮箱 Token 和公共 API Key 使用 AES-GCM 加密。
- `.db`、`.key`、`config.json` 权限为 `0600`，数据目录为 `0700`。
- 管理员密码使用随机盐 PBKDF2-SHA256。
- 会话 Token 使用加密随机数，数据库只保存 SHA-256 摘要。
- Cookie 为 HttpOnly、SameSite Strict，Secure 由配置控制。
- API Key 和邮箱 Token 使用常量时间比较。
- 所有 `/api/` 响应统一 `Cache-Control: no-store`；SSE 单独使用 `no-cache, no-transform`。
- JSON 请求体有大小限制并拒绝尾随第二个 JSON 对象。
- 没有开放 CORS。
- Vue 未使用 `v-html`、`innerHTML`、`eval` 或动态脚本注入。
- 邮件正文通过 Vue 文本插值显示。
- Apple/iCloud HTTP 和 IMAP 均配置超时。
- IMAP TLS 最低版本为 1.2，并校验证书。
- SSE 支持事件序号、持久化变更日志、断线回放与心跳。
- 邮箱同步按账号合并，并在一个 SQLite 事务中写入消息与游标。

## 9. 修复顺序

### 第一批：立即处理

1. 升级 Go 1.26.6 或更新补丁版本并重新构建。
2. 把远端邮件收件人匹配改为规范邮箱地址等值匹配并增加相似地址测试。
3. 增加 Host allowlist、可信代理和固定公网 `public_base_url`。
4. 为登录、首次设置和公共接口增加限流。
5. 为公共验证码增加访问凭证、统一错误和审计。

### 第二批：公网发布前

1. 管理写接口 Origin/CSRF 防护。
2. Apple/iCloud 服务 URL allowlist。
3. 服务层字段长度和调度范围上限。
4. API Key Header 默认策略与 Token 轮换。
5. HTTPS、`secure_cookie=true`、CSP 和 Permissions-Policy。

### 第三批：维护改进

1. 远端邮箱同步删除对账。
2. 敏感导出二次确认、审计和可选密码保护。
3. 清理 Staticcheck 项。
4. 完整弹窗 focus trap。
5. 确定签名、守护进程和回滚后再实现自动更新。

## 10. 最终判断

当前版本适合单管理员、本机运行场景，功能、数据和实时更新架构已经完成重构。公网发布的主要门槛不是 SQLite 或 UI，而是远端删除匹配边界、Go 标准库补丁、Host、限流、CSRF 和公共验证码访问控制。

后续完成第一批和第二批修复后，应使用 Go 1.26.6 或更新版本重复本报告的测试、静态扫描和浏览器巡检，并更新审计日期与结论。
