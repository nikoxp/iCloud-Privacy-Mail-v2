# SQLite 升级、备份与恢复

> 更新日期：2026-08-15
>
> 项目来源：[xiuxiu56/iCloud-Privacy-Mail-v2](https://github.com/xiuxiu56/iCloud-Privacy-Mail-v2)

## 数据原则

`data/app.db` 是唯一业务数据源。服务不读取、不生成也不兼容迁移 `state.json`。数据库结构通过 `schema_migrations` 管理，启动时在事务中顺序执行未应用迁移。

当前数据库 schema 版本为 4。

## 升级前

1. 确认当前服务运行正常。
2. 在“系统设置 → 本地数据”执行“完整性检查”。
3. 点击“立即备份”，等待 `.db` 和 `.db.key` 都生成成功。
4. 记录当前程序版本、Git commit 和数据库 schema 版本。
5. 使用 Go 1.26.6 或更新补丁版本构建新程序。

在线备份会生成：

```text
data/backups/app-时间.db
data/backups/app-时间.db.key
```

两者必须成对保存。`.db.key` 用于解密 Apple Cookie、登录态、IMAP App 专用密码、邮箱 API Token 和公共 API Key。

## 自动升级

正常替换程序并启动即可。Store 打开数据库后会：

1. 配置 WAL、busy timeout 和关系保护。
2. 创建或读取 `schema_migrations`。
3. 按版本执行缺失迁移。
4. 校验基础表和索引。
5. 启动 SSE、后台维护、租约回收和任务恢复。

升级失败时应保留原数据库和日志，不要反复覆盖备份。

## 日常维护

- 本地邮件默认保留 90 天。
- 在线备份默认保留 14 天。
- SSE 变更日志默认保留 5000 条。
- 后台每天执行邮件保留清理、在线备份和 WAL checkpoint。
- 系统设置页提供完整性检查、立即备份和空间整理。

相关配置：

```json
{
  "database_backup_dir": "data/backups",
  "database_backup_retention_days": 14,
  "database_message_retention_days": 90,
  "database_change_log_limit": 5000
}
```

不要直接复制正在写入中的 `app.db` 作为唯一备份；WAL 模式下应使用系统提供的在线备份或 SQLite 一致性备份机制。

## 恢复

1. 停止服务。
2. 备份当前故障数据库与密钥供排查。
3. 把选定备份 `.db` 复制为配置中的 `data_path`。
4. 把配套 `.db.key` 复制为 `data_path + ".key"`。
5. 设置数据目录权限为 `0700`，数据库和密钥权限为 `0600`。
6. 启动服务。
7. 在系统设置执行完整性检查，并核对账号、邮箱、邮件、租约和调度状态。

示例目标：

```text
data/app.db
data/app.db.key
```

密钥与数据库不配套时，加密字段解密会失败，应立即停止服务并换回正确的一对备份。

## 回滚

程序升级后如需回滚：

1. 停止新程序。
2. 查看旧程序是否支持当前 schema。
3. 若不支持，恢复升级前的 `.db` 和 `.db.key`。
4. 启动旧程序并执行完整性检查。

不要让两个版本同时写同一个 SQLite 数据库。
