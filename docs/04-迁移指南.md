# 迁移指南

## 迁移前

1. 停止旧 Go 服务，复制旧 `data/state.json` 做只读备份。
2. 先构建新项目，确认 `bin/ipm-migrate` 存在。
3. 为新项目准备 `config.json`，确认 `data_path` 指向新项目的 `data/state.json`。

## 执行迁移

```bash
./bin/ipm-migrate \
  -source "/旧项目/data/state.json" \
  -target "/新项目/data/state.json"
```

目标文件存在时命令会停止，确认备份后再使用：

```bash
./bin/ipm-migrate -source "/旧项目/data/state.json" -target "data/state.json" -force
```

## 字段映射

| 旧字段 | 新字段 | 处理 |
| --- | --- | --- |
| `users[is_admin]` | `admin` | 选择管理员，去掉多用户数组 |
| `accounts` | `apple_accounts` | 保留账号展示字段 |
| `mailboxes` | `mailboxes` | 保留 `anonymous_id`、状态和统计，API Token 只存储不回传 |
| `messages` | `messages` | 保留邮件缓存 |
| `icloud_session` | `icloud_sessions[]` | 转成 typed `ICloudSession`，保留 Cookie 和登录态字段 |
| `icloud_sessions` | `icloud_sessions[]` | 转成 typed `ICloudSession`，合并同一账号登录态 |
| `web_sessions` | `sessions` | 不迁移，避免旧登录态直接复用 |

迁移工具会写入 schema version 3、创建设置、默认设置和迁移事件，并清空会话。迁移成功后，第一次打开新版页面时如果已有管理员会直接显示登录页；Apple 登录态可在 Apple 账号页检测和继续使用。

## 回滚

新版只写新目标文件。出现问题时停止新版、保留新 `data/state.json` 供排查，再用旧备份恢复旧服务的数据文件；不要让两个版本同时写同一个状态文件。
